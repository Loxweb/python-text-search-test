# Поиск по текстам документов

Это простой сервис, который ищет слова и фразы в документах из `posts.csv`. Введите запрос на странице, и сервис покажет до 20 совпадений, начиная с самых новых. У каждого результата видны текст, дата и рубрики. Документ можно удалить со страницы: он будет удалён и из базы, и из поискового индекса.

Для поиска используется Elasticsearch, а SQLite хранит полные записи. API сделан на FastAPI. Веб страница, API и сам импорт данных уже включены в проект.

## Данные для запуска

В репозитории есть небольшой демонстрационный набор `data/posts.example.csv`. Полный файл `posts.csv` в Git не включён: в исходных текстах могут встречаться телефоны и другие личные данные. Для демонстрационного запуска скопируйте пример в ожидаемое имя файла:

```powershell
Copy-Item data/posts.example.csv data/posts.csv
```

Если у вас есть исходный набор из задания, положите его вместо `data/posts.csv`. Этот файл исключён из Git и Docker образа.

## Запуск в Docker

Нужен установленный и запущенный Docker Desktop. Откройте PowerShell и перейдите в папку проекта:

```powershell
cd "$env:USERPROFILE\Desktop\python-text-search"
docker compose up --build
```

При первом запуске Docker скачает Elasticsearch. Затем сервис загрузит документы из `data/posts.csv` в базу и индекс. Это может занять несколько минут. После запуска откройте в браузере:

- Поисковая страница: <http://localhost:8000>
- Документация API: <http://localhost:8000/docs>
- OpenAPI в формате JSON: <http://localhost:8000/openapi.json>
- Elasticsearch: <http://localhost:9200>

Чтобы остановить приложение, нажмите `Ctrl+C` в окне PowerShell. Если хотите запустить его в фоне, используйте `docker compose up --build -d`. Остановить фоновый запуск можно командой `docker compose down`.

База SQLite находится в папке `data`, а данные Elasticsearch хранятся в Docker volume. Поэтому записи сохраняются после остановки контейнеров.

## Запуск API локально

При таком запуске сам Python сервис работает на компьютере, а Elasticsearch всё ещё запускается через Docker. Нужны Python 3.12 и Docker Desktop.

Сначала запустите Elasticsearch из папки проекта:

```powershell
docker compose up -d elasticsearch
```

Затем создайте виртуальное окружение, установите зависимости, загрузите набор данных и запустите API:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python -m app.ingest
python -m uvicorn app.main:app --reload
```

На Linux или macOS используйте такие команды для виртуального окружения:

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m app.ingest
python -m uvicorn app.main:app --reload
```

После запуска страница будет доступна по адресу <http://localhost:8000>.

## Как пользоваться API

### Найти документы

Отправьте `POST` запрос на `/api/v1/search` с текстом для поиска:

```json
{
  "query": "городская инфраструктура"
}
```

В ответе будут найденные документы с полями `id`, `rubrics`, `text` и `created_date`. Результатов будет не больше 20. Пустой запрос сервис отклонит.

### Удалить документ

Отправьте `DELETE` запрос на `/api/v1/documents/{id}`, подставив ID документа. Сервис удалит его из SQLite и Elasticsearch. Если такого документа нет, вернётся ответ `404`.

### Проверить состояние

Откройте `GET /api/v1/health`, чтобы увидеть статус сервиса и количество записей в базе.

## О наборе данных

В CSV 1500 документов. В файле есть колонки `text`, `created_date` и `rubrics`, но нет `id`. Поэтому при импорте каждой строке присваивается постоянный ID: `post-000001`, `post-000002` и так далее. Рубрики хранятся в SQLite как список. В поисковом индексе, как требует задание, находятся только ID и текст.

Сервис получает из Elasticsearch до 10 000 найденных ID, затем выбирает в SQLite двадцать самых новых документов. В текущем наборе всего 1500 записей, поэтому поиск учитывает все совпадения. Если набор сильно вырастет, верхний предел можно изменить переменной `MAX_SEARCH_CANDIDATES`.

## Настройки

Для запуска через Docker менять настройки не нужно. При локальном запуске можно задать переменные среды. Их названия и значения по умолчанию приведены в `.env.example`:

| Переменная | Значение по умолчанию | Что настраивает |
|---|---|---|
| `ELASTICSEARCH_URL` | `http://localhost:9200` | Адрес Elasticsearch |
| `ELASTICSEARCH_INDEX` | `documents` | Название поискового индекса |
| `DATABASE_PATH` | `./data/search.db` | Путь к файлу SQLite |
| `DATASET_PATH` | `./data/posts.csv` | Путь к CSV файлу |
| `MAX_SEARCH_CANDIDATES` | `10000` | Сколько совпадений запрашивать у Elasticsearch |

## Тесты

Тесты запускаются без Elasticsearch: для проверки API в них используется тестовая заглушка поискового индекса. Создайте и активируйте окружение, установите зависимости, затем выполните:

```powershell
python -m pytest -q
```

Тесты проверяют выдачу полных документов, сортировку по дате, ограничение в 20 результатов, удаление и обработку пустого запроса.

После изменения API обновить файл `docs.json` можно командой:

```powershell
python -m app.export_openapi
```
